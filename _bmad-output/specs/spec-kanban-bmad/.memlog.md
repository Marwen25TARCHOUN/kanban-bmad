- (event) Create spec. Inputs: brief + addendum + PRD (29 FRs / 9 NFRs, status=final) + DESIGN.md + EXPERIENCE.md + ARCHITECTURE-SPINE.md (15 ADs, status=final). - (direction) Why: pain-to-solve + portfolio-artifact combination. The solo developer losing 10-15 minutes translating a fuzzy one-line idea into step-sized Kanban cards (SaaS tools are structured but demand manual breakdown; LLM chats produce usable output but force the user out of flow). The pain is real but low-urgency, so side projects stall at 'I know what I want, I just haven't started'. Backdrop: a one-week portfolio build whose success doubles as a Java/Angular interview artefact (France, 2026-11-27).
- (capability) CAP-1 Board & Card CRUD. intent: a user manages Kanban cards across three fixed columns (To Do / In Progress / Done) via a quick-add control, inline edits of title/description/priority, inline-confirm delete, drag across columns, and drag to reorder within a column. success: FR-1..FR-7 all demonstrable in the live demo with drag-drop perceived latency <100 ms (NFR-1); every mutation persists before the next interaction.
- (capability) CAP-2 AI breakdown (flagship). intent: a user turns a one-line idea (1-500 chars, trimmed) into 4-6 accept-ready cards in one gesture — enter the idea, see the preview modal, tick/edit titles, accept, cards land in To Do with their ✨ badge. success: FR-9..FR-16 green with end-to-end p95 <10 s (NFR-2); the strict server-side validator (schema + count in [4,6]) blocks every malformed response at the service layer before the UI sees it; at most one breakdown in flight at a time.
- (capability) CAP-3 AI-origin marker. intent: a user can tell at a glance, forever, which cards originated from the AI. success: every card with aiGenerated=true renders a ✨ badge beside the title; the flag is set at AI-accept time and is never cleared by subsequent edits (FR-8 + architecture AD-14).
- (capability) CAP-4 Bilingual UI with runtime switch. intent: a user operates the UI in French or English and flips between them without reload; AI-generated content follows the locale active at the moment of generation and never retranslates. success: FR-17..FR-20 green; locale persists in localStorage with navigator-language fallback; AI-generated cards stamp a generationLocale on the entity (architecture AD-10, AD-14) so DOM nodes carry lang=<generation-locale> at render.
- (capability) CAP-5 Local durable persistence. intent: the user's board survives shutdown and restart with no configuration step. success: FR-21..FR-22 green — embedded H2 file DB (./kanban.mv.db dev, /data/kanban.mv.db containerized); ddl-auto=update owns schema; no data loss across clean shutdown; the integration test boot→write→restart→read passes (NFR-7).
- (capability) CAP-6 Zero-install startup (two modes). intent: a reviewer cloning the repo runs the app in two commands or fewer. success: FR-23 + architecture AD-15 green. Primary path: Docker Desktop installed, then .\start-windows.ps1 / ./start.sh / start.bat — one command, both services up, URLs printed. Dev-mode fallback: ./mvnw spring-boot:run + npm start. NFR-5 holds: no .env editing, no manual schema setup.
- (capability) CAP-7 Graceful degradation without an API key. intent: the app is fully functional for manual card management even when ANTHROPIC_API_KEY is absent; AI-related UI is hidden (not disabled, not errored). success: FR-24..FR-25 green. @ConditionalOnProperty omits AiBreakdownController and the Anthropic RestClient bean when the key is absent; GET /api/config returns {aiEnabled: false} and the frontend removes the AI breakdown bar from the DOM entirely. The frontend never checks the env var directly (architecture AD-6).
- (capability) CAP-8 AI failure recovery. intent: when an AI call fails for any reason during an in-flight breakdown, the user sees a localized toast, their idea stays in the input, and they can retry without retyping. success: FR-26..FR-29 green. 503 { error: AI_UNAVAILABLE, message } is the sole upstream-failure response class (architecture AD-2); the modal does not open on failure; the toast auto-dismisses in 5 s and has a close affordance; input retains the idea. Pre-call input errors are 400 VALIDATION_FAILED, distinct from 503 (architecture AD-5).
- (constraint) One-week budget ending 2026-11-27. Scope cuts and trade-offs favor demo-day readiness over production hardening. Rules out: CI/CD automation, cloud deploy, auth, multi-user features, Flyway migrations, resilience layers (retry/circuit-breaker).
- (constraint) Single-user, local-only. The app runs on one developer's machine; no shared state, no auth, no Authorization header parsing. Rules out: user profiles, multi-tenant data models, any 'who did what' telemetry.
- (constraint) Stack pinned (architecture Stack table, web-verified 2026-11-20): Java 21 LTS, Spring Boot 4.1.x, H2 2.5.x (embedded file mode), Lombok 1.18.38+, Angular 22.x + @angular/cdk 22.x, ngx-translate 18.x, Node 22 LTS, Anthropic Messages API (anthropic-version 2026-10-21, model claude-opus-4-7) via Spring RestClient, Docker Engine + Compose v2, eclipse-temurin:21-jre-alpine (backend runtime), nginx:1.27-alpine (frontend runtime). Rules out: alternative LLMs, alternative HTTP clients, alternative static servers.
- (constraint) Classic layered architecture on the backend (architecture AD-1): controller -> service -> repository with dto/mapper at the controller boundary; entities never leave the service layer; controllers never touch JPA repositories directly; no cross-service dependencies. Rules out: hexagonal/ports-and-adapters, event-sourcing, CQRS.
- (constraint) Signal-reactive frontend (architecture AD-9): one BoardStore service holds board state as WritableSignal<Card[]>; components read via computed() only and never mutate signals directly; ApiService is the sole HttpClient consumer. Rules out: half-store / half-direct patterns; RxJS BehaviorSubject stores.
- (constraint) Server-authoritative enums + position (architecture AD-3, AD-4). CardStatus = {TODO,IN_PROGRESS,DONE}, Priority = {LOW,MEDIUM,HIGH} serialized UPPER_CASE; position zero-indexed per status with UNIQUE(status, position) + SELECT FOR UPDATE on renumber. No Column entity. Rules out: client-side ordering, Lexorank-style sparse keys, integer-gap management.
- (constraint) AI output is validated twice (architecture AD-5): structured-output schema (output_config.format type: json_schema) forces valid JSON at the Anthropic layer AND a strict Jackson validator rechecks on receive. Pre-call validation errors return 400; post-call failures return 503 AI_UNAVAILABLE. Rules out: partial parsing, raw-text LLM output in happy path, 200 with empty cards, 503 for input validation.
- (constraint) Batch accept is atomic all-or-nothing (architecture AD-8): POST /api/cards/batch body = full card payloads (title/description/priority — server owns id/position/aiGenerated/generationLocale); either every selected card persists or the whole batch rolls back. Single-card mutations are optimistic with snapshot rollback on failure. Rules out: 207 Multi-Status, server-side queued preview state, half-committed batches.
- (constraint) PATCH three-state semantics (architecture AD-13): DTO fields use JsonNullable; absent = ignore, value = update, null = clear (only on nullable fields such as description). Required fields reject null with 400. Rules out: null-means-ignore and null-means-erase both being valid.
- (constraint) Localization split (architecture AD-10): UI chrome via ngx-translate keys; AI-generated card content stored verbatim in generationLocale with no retranslation; user-typed content never translated. DOM renders lang=<generationLocale> when aiGenerated=true. Rules out: translating AI content post-hoc; translating user content; using the active UI locale as the lang stamp at render.
- (constraint) Test shape fixed (architecture AD-11, NFR-7): three layers only — (1) pure JUnit 5 + AssertJ unit tests on AiBreakdownParser/Validator and services with branching domain logic; (2) @WebMvcTest per controller for happy + validation-failure; (3) one @SpringBootTest boot→write→restart→read integration test. No E2E, no Playwright, no frontend unit tests in MVP. Rules out: adding a fourth layer during build.
- (constraint) Two run modes first-class (architecture AD-15). Primary: Docker Compose two-service (backend + frontend behind nginx reverse proxy at /api), named volume kanban-data for H2, healthcheck via /actuator/health, depends_on service_healthy. Dev-mode fallback: ./mvnw spring-boot:run + npm start on ports 8080/4200 with CORS allow-origin http://localhost:4200 (architecture AD-12). Rules out: a third run mode; CORS being exercised in containerized mode.
- (constraint) WebClient idiom replaced by RestClient (architecture AD-5 revision). Spring Boot 4.1 provides spring-boot-starter-restclient; the Anthropic bean is gated by @ConditionalOnProperty(name='anthropic.api-key', matchIfMissing=false) so the whole AI graph omits when the key is absent. Timeouts: 10 s connect, 30 s read; no retry. Rules out: silent retry, WebClient-based AI calls, hardcoded aiEnabled flag.
- (constraint) A11y floor documented (architecture + EXPERIENCE.md + NFR-9): columns rendered as <section aria-labelledby><h2>, icon-only buttons carry localized aria-labels, decorative sparkles aria-hidden, AI loading announces via polite live region with aria-busy, html.lang updated on locale switch, AI card content stamped lang=<generation-locale>, reduced-motion carve-out covers card-entry stagger + delete fade + pulse + drag tilt + modal blur + toast slide, target-size floor 24x24 CSS px WCAG 2.5.8. Rules out: hover-only interactions, title= as the sole accessible name, decorative emoji read as text.
- (constraint) Privacy and network boundary (NFR-6): the only outbound call the app makes is the Anthropic HTTPS request, and only when the user explicitly presses ✨ Break down. No telemetry, no analytics, no crash reporter, no 'phone home'. Rules out: adding any outbound call during MVP; background sync; opt-out telemetry defaults.
- (decision) Non-goal: multi-user, authentication, user profiles. Any Authorization header is ignored. Introduction of users is a new spec, not an amendment.
- (decision) Non-goal: cloud sync, multi-device, remote storage, external backup. H2 lives on disk; losing the laptop loses the board.
- (decision) Non-goal: native mobile. Responsive web is a stretch; the app targets 1280x800+ (EXPERIENCE.md Foundation).
- (decision) Non-goal: card comments, attachments, custom labels, tags, due dates, estimated-effort fields, assignees. The three fields a card carries (title, description, priority) are the whole product; adding a fourth is scope creep.
- (decision) Non-goal: notifications of any kind (in-app, system, email, push). Local single-user app.
- (decision) Non-goal: multiple projects or boards. One global board. Multi-project is the 12-month vision track, not MVP.
- (decision) Non-goal: automatic archival of Done. Cards grow indefinitely; user deletes manually.
- (decision) Non-goal: AI chat on cards, AI-assisted card edit, AI retrospectives, streaming AI responses. The AI appears once per session, at breakdown time only. A chat surface drifts the product away from its 'momentum never breaks' promise.
- (decision) Non-goal: multi-environment deployment scripts beyond local run. CI/CD, cloud deploy, registry push are documented as deferred in the architecture spine and solution-design doc, not in scope this week.
- (decision) Non-goal: analytics, telemetry, usage metrics, crash reporters. Privacy is a first-class design decision (NFR-6).
- (decision) Non-goal: full WCAG 2.1 AA audit. The accessibility floor (keyboard nav, semantic HTML, focus trap, CDK ARIA, reduced-motion carve-outs, target-size 24x24) is in; a compliance audit, screen-reader E2E, and color-contrast sign-off are out per NFR-9.

A reviewer running git clone + one command on a clean machine with Docker Desktop installed reaches the same board within three minutes.
