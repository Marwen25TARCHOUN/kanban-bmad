- (decision) AI acceptance UX: Model A — preview modal, batch-accept. User types fuzzy idea → clicks ✨ Break down with AI → modal shows 4-6 generated cards (tick/untick, inline-edit) → Accept selected drops into To Do. Clean gate, one AI call, boring-good backend. Rejected B (direct insertion — no gate) and C (streaming — too complex for 1 week).
- (decision) Graceful degradation: 1(b) missing API key → conditional bean (@ConditionalOnProperty), endpoint not registered, frontend probes /api/config to hide the AI button — no crash, no 404-looking-like-a-bug. 2(a) runtime failure → single-shot call, toast error 'AI service unavailable, try again', modal does not open. 3(a) malformed/0-card response → treat as error, toast, do not open modal. Strict JSON validation before any UI render.
- (decision) Board model: Model 1 — single global Kanban board. Schema: just Card entity. Trade-off accepted: narrows the 'junior PM juggling projects' story; primary users become solo devs + students; junior PM is aspirational/secondary. Rationale: 1-week budget prefers depth of AI flagship over CRUD breadth; keeps Spring Data JPA clean through layered design, not relationship gymnastics.
- (decision) Card schema: id (UUID), title (≤120), description (≤2000), priority (enum LOW/MEDIUM/HIGH, default MEDIUM), status (enum TODO/IN_PROGRESS/DONE, from column), position (int, within column), createdAt (timestamp), aiGenerated (bool, ✨ badge). AI JSON contract: [{title, description, priority}] × 4-6 — backend wraps with id/status=TODO/position/createdAt/aiGenerated=true. Rejected for MVP: tags, dueDate, estimatedEffort.
- (decision) UI language: Bilingual (French + English) with runtime switcher. Defense (user's own words): 'FR/EN switch is a 30-second demo moment with disproportionate impact — recruiter sees the AI break down the same idea in two languages with no code change, and it signals I can wire i18n end-to-end, something most enterprise Angular shops expect by default.' Overrode Mary's conservative FR-only recommendation. AI output language: match the active locale at request time (passed as a parameter to the AI prompt).
- (decision) i18n engine: ngx-translate. Rationale: runtime locale switch is first-class in ngx-translate and a workaround in @angular/localize; live-demo 'no code change, no reload' UX drove the choice. Defense answer if challenged: 'live-demo UX need over framework-native tooling'.
